# Changelog

All notable changes to this project will be documented in this file.

## [5.1.0] - 2026-11-23

### Added
- **Drop Instagram's ZIP as it is.** The page opens the "Download your information" ZIP itself and picks out following, followers
  and recently unfollowed (HTML or JSON); nothing else in the ZIP is decompressed. Needs no unzipping or renaming. The export
  day is read from the HTML or, failing that, from the ZIP's file name. ZIPs over 1 GB are refused with advice.
- `samples/instagram-sample-export-2026-11-20.zip` to try it.

### Changed
- The page no longer keeps your lists in the browser between visits: it starts empty and the workbook is the only copy.
  The old saved copy is removed on load.

## [5.0.0] - 2026-11-21

### Changed
- **The project is now called Artisya Yan?!** (page title, header, README, package name).
- The page header and footer show the author's picture and name. The picture is embedded in the page (it is one file and its
  security policy only allows embedded images); `npm run profile` re-embeds it from `assets/profile-small.png`.
- A fresh start: the repository begins with a single clean commit.

## [4.0.0] - 2026-11-21

### Added
- **Who unfollowed you, with proof.** The workbook gets a `followers_snapshot` sheet (`username`, `profile_link`, `first_seen`, `last_seen`), written on every save. Load a newer Instagram export with it and the page shows new followers, lost followers, and an **Unfollowed you** list of lost followers nobody has explained yet ("followed you until ...").
- A lost follower is not always an unfollow (deactivated, deleted, renamed and blocked accounts vanish too), so the recheck works on this tab: the profile opens = unfollowed you (recorded in the `unfollowed` column), the page is gone = marked deactivated.
- The export's generation day is read from the HTML (`<time datetime>`); JSON files use the file's date. The first export is a baseline, an older export than the last snapshot is ignored, and loading the same export twice changes nothing.
- Sample dataset: the sample workbook now holds an earlier snapshot (3 new followers, 4 lost, 3 to check) and the README has a new screenshot and step for it.

### Changed
- The workbook now has a fourth managed sheet; older workbooks get it on the first save. Saved browser copies are migrated.

## [3.2.0] - 2026-11-21

### Added
- **Faster recheck:** choose 5, 10 or 20 tabs per round; "recheck again after" never / 30 / 90 / 180 days (an account checked recently is skipped); order newest follow first, oldest first or A to Z; keyboard keys U (unavailable), W (works) and A (all unavailable) for the highlighted account. Settings are remembered.
- **Recheck results live in the workbook:** two new `white_list` columns, `last_checked` and `check_result`, so a result goes with the file instead of staying in one browser. Older workbooks get the columns on the first save.
- **The workbook stays yours:** columns of your own and other sheets are kept as plain values when you save; your column order and row order are kept (new accounts go at the end). The page reports what it kept on load.

### Changed
- The white_list sheet is no longer re-sorted alphabetically on save.
- A header that is present but lacks a column is no longer "guessed" by position, so a custom column can never be mistaken for a standard one.
- Excel's typed dates (day numbers) in `last_checked` / `unfollowed_on` are read as real dates.

## [3.1.0] - 2026-11-21

### Added
- **Recheck now covers whitelisted accounts** too. Being whitelisted says nothing about whether an account is still active: "Unavailable" marks it `is_deactivated` and it stays whitelisted (both marks); "Works" clears the mark.
- **Sample dataset** (`samples/`): a made-up workbook plus Instagram-format HTML files, generated by `npm run samples`, so the guide can be followed (and the result checked) without any real data.
- **README rewritten as a step-by-step guide** with new screenshots of the offline checker, including how to upload the sample Excel file.

### Removed
- The old screenshots of the online scanner.
- The author attribution lines from the README, the scanner page footer and page titles (the `LICENSE` file keeps the MIT copyright notice, which the license requires).

## [3.0.0] - 2026-11-21

### Changed
- **The offline checker is now the landing page** (`docs/index.html`). `offline.html` redirects to it. The online scanner moved to
  `docs/scanner.html` (and is linked from the page footer). `npm run build` generates all three; the PR guard protects all three.

### Added
- **Recheck deactivated accounts:** "Open next 5 tabs" opens five profiles at once; you press Unavailable (the page says
  "Sorry, this page isn't available") or Works (clears the deactivated mark) for each. Results are remembered in the browser, the
  next round opens the next five, and a blocked pop-up is detected and explained.

## [2.2.0-offline] - 2026-11-21

### Added
- **View button** on every row: opens the account's Instagram profile in a new tab.
- **Active again** tab: accounts your sheet marks deactivated / deleted that now follow you (a deactivated or deleted account cannot be a follower). A "Clear mark" button removes the mark.
- **Missing** tab: accounts from your sheet that are gone from both lists and that you did not unfollow: likely deleted (Instagram hides which account is deleted) or renamed. Buttons: Mark deleted, Renamed, Unfollowed.
- `recently_unfollowed_profiles.html` is read (it has no links, only Name / Username tables) so an account you unfollowed is not mistaken for a deleted one. Other lists of the download (close friends, favorites, ...) are recognised and ignored.

## [2.1.0-offline] - 2026-11-21

### Added
- **HTML export support:** `following.html` and `followers_1.html` from the Instagram download are read directly (JSON still works).
- `is_deleted` column (7th) and a **Deleted** tab; accounts Instagram lists as `__deleted__...` are detected automatically.
- Checked against a real export: the page reproduces the follower / following counts and the workbook round-trips every flag.

## [2.0.0-offline] - 2026-11-19

### Added
- **Offline mode** (docs/offline.html): compares your Instagram data-export files (following.json, followers_*.json)
  with no network access at all (enforced by a Content-Security-Policy). Review who does not follow back, whitelist,
  mark accounts deactivated or renamed, and log unfollows.
- **Base workbook** (templates/ig_whitelist_template.xlsx): white_list, new_followingxfollowers and unfollowed tabs.
  The page loads and saves it as .xlsx (Excel / Google Sheets compatible).
- `unfollowed` column in white_list (accounts proven to have unfollowed you, for tracking) with an "Unfollowed you" tab.
  Columns are found by header name, so any order works and older workbooks without it still load.
- Accounts with a new_username that follow you under that name are not reported as non-followers.

## [1.6.1] - 2026-11-19

### Fixed
- A list request that never answered could freeze the scan forever with no message; every request now has a 30 s
  deadline and is retried like any network error.
- Scan waits run in a Web Worker so a background / covered tab no longer slows them to a crawl (falls back to normal
  timers where workers are blocked).

## [1.6.0] - 2026-11-19

### Changed
- **Results appear right away.** The scan now loads the accounts you follow first and lists them immediately as
  provisional candidates, then walks your followers and removes anyone who follows you back, so the list shrinks to the
  real non-followers while you watch. Previously nothing was shown until the entire followers list had been downloaded.
- Selecting, whitelisting and unfollowing stay locked until the scan finishes (a clear banner explains why), so an
  unfinished list can never be acted on. An interrupted scan warns that the list may still include accounts that follow
  you back.
- Saved scan progress (from 1.5.0) follows the new order. Progress saved by the older build is ignored. Avatar URLs are
  not stored in saved progress, so a resumed scan shows placeholder pictures until the next full scan.

## [1.5.0] - 2026-11-18

### Added
- **Scan survives a reload:** progress is saved in the browser (every few pages, when the tab is hidden, and when a scan
  stops). After a discarded or reloaded tab, re-run the script and press "Resume interrupted scan". Saved progress is
  per account, expires after 6 hours, and is rejected if it looks damaged.

### Changed
- **Pause reacts almost instantly** (within ~250 ms): every scan delay, the periodic safety sleep and the post-cooldown
  retry now honour Pause. Request pacing itself is unchanged.

## [1.4.0] - 2026-11-18

### Changed
- **New visual identity** ("paper & ink"): warm off-white / violet / mint palette, chunky outlines with offset shadows,
  rounded system font stack, a new ghost mascot, and a card-grid results view with a letter-divider rhythm.
- Light and dark themes (follows the system; toolbar button cycles Auto / Light / Dark and remembers the choice).
- Launch screen rebuilt around a 3-step flow (Scan, Review, Unfollow). Responsive down to phone width.
- Copy page rebuilt: no third-party fonts or scripts (zero external requests), collapsible code viewer, size and
  SHA-256 fingerprint of the script, clearer instructions.
- Old whitelist entries pasted by username no longer reference a third-party avatar service.

## [1.3.0] - 2026-11-18

### Added
- **Resume scan:** an interrupted scan keeps a checkpoint and continues from the page that failed (no re-download).
- Exponential backoff with jitter, `Retry-After` support, retry of 5xx/network errors, adaptive request pacing.
- Input validation layer for everything read from storage/imports; unit tests and an end-to-end scenario.
- CI: typecheck, lint, tests and production `npm audit` gate the Pages deploy.

### Security
- Whitelist now protects by username as well as id (pasted usernames were not protected before).
- Unfollow queue re-checks the whitelist and refuses non-numeric ids; aborts on account switch or 3 consecutive failures.
- Fixed path/link injection via tampered storage or imported files; cached scans expire after 24 h and partial scans are never cached.
- Removed third-party avatar requests (dicebear); timings clamped to the safe range.
- Dependencies updated (36 advisories -> 0 in production); Node 22; stale ESLint config replaced.

## [1.2.0] - 2026-04-04

### Added
- **Whitelist Star Button:** Dedicated star (★) button on each profile row for instant whitelist management.
- **Sticky Actions:** The "UNFOLLOW" button is now fixed at the bottom of the sidebar for constant accessibility.
- **Anti-Detection Measures:** Randomized micro-pauses (500ms-2k ms) and dynamic sleep cycles (+/- 5s randomization) to mimic human behavior and avoid Instagram rate limits.
- **Data Persistence:** Whitelist state and scan timing settings are now saved in `localStorage`.

### Changed
- **UI Density:** Restructured sidebar layout to be more compact. Combined "Pause" and "Pagination" into a single row.
- **Grid Layouts:** Filters and Smart Select buttons are now organized in a 2-column grid, reducing vertical height by 50%.
- **Scan Summary:** Modernized the summary layout with a 3-column grid and clearer labels ("Private" instead of "P").
- **Visuals:** Updated sidebar with glassmorphism effects and optimized scrollbars.

## [1.1.0] - 2026-03-10

### Added
- **Smart Selection (UX Improvements):**
  - Added "Select Verified" button to quickly select all verified users.
  - Added "Select Private" button to select all private accounts.
  - Added "Select No Profile Pic" button to identify and select users without a profile picture (useful for bot cleanup).
  - Added "Clear Selection" button to reset the current unfollow queue.
- **Data Exporting Tools:**
  - Added "JSON Export" button in the toolbar to download filtered results as a JSON file.
  - Added "CSV Export" button in the toolbar to download filtered results as a CSV file (compatible with Excel).
- **Profile Preview:**
  - Implemented high-quality avatar preview on hover. Passing the mouse over a user's avatar now shows a large, clear version of their profile picture.
- **Style Enhancements:**
  - Created `_ux_improvements.scss` with refined button styles, layout gaps, and preview animations.

### Changed
- **Technical Robustness:**
  - Refactored selection logic to be 100% compatible with ES5 (fixing Set iteration errors in older browsers).
  - Improved TypeScript typings across all Icon components.
  - Optimized `getUsersForDisplay` utility with new helper functions.

### Fixed
- Fixed issues where the build would fail due to missing dependencies (restored via `npm install`).
- Fixed several "Implicit Any" and JSX typing errors in the component tree.

# Historial de Cambios (Spanish)

Todos los cambios notables en este proyecto serán documentados en este archivo.

## [1.2.0] - 2026-04-04

### Añadido
- **Botón de Estrella (Whitelist):** Botón (★) dedicado en cada usuario para añadir o quitar de la lista blanca al instante.

- **Estética:** Actualizado el lateral con efectos de desenfoque (glassmorphism) y optimización de barras de scroll.
